# 客服工单分析工具

## 背景

客服主管每天要关注大量工单数据，需要快速了解：最近哪些问题变多了？哪些异常需要关注？目前靠人工翻看工单列表，效率很低。

本工具用 C++ 实现，自动读取工单数据，从多个维度进行统计分析、识别异常信号，并生成一个**中文交互式 HTML Dashboard**（基于 ECharts），帮助主管把精力放在真正需要关注的事情上。

## 分析维度设计

针对 `task5_tickets.json` 的 50 条工单（2024-06-01 ~ 06-11），设计了 8 个分析维度：

| # | 维度 | 分析内容 | 对主管决策的价值 |
|---|------|---------|----------------|
| 1 | 时间趋势 | 按天聚合工单量、未解决数 | 识别工单激增日，决定是否加派人手 |
| 2 | 类型分布 | 各分类占比 | 定位最耗精力的核心问题域 |
| 3 | 优先级分布 | 高/中/低占比及平均满意度 | 评估紧急工单压力与资源配比 |
| 4 | 处理时长 | 各分类平均/最长时长(箱线图) | 定位流程瓶颈(哪些问题迟迟解决不了) |
| 5 | 满意度 | 满意度分布 + 各分类/渠道平均分 | 定位低满意度的根因环节 |
| 6 | 渠道分析 | 在线/电话/邮件的量、时长、满意度 | 评估各渠道服务质量 |
| 7 | 解决率 | 未解决工单按分类/渠道拆分 | 识别积压与遗漏 |
| 8 | 关联分析 + 关键词聚类 | 处理时长↔满意度相关趋势；描述关键词频次 | 发现反复出现的共性问题 |

## 关键发现

### 整体概况

- 工单总数 **50**，未解决 **8** 笔（16%）
- 平均满意度 **2.36** 分（偏低），平均处理时长 **19.69** 小时
- 优先级分布：高 **31** 笔（62%）、中 13 笔、低 6 笔 —— 紧急工单占主导，处理压力大

### 趋势

- **两大核心问题域**：支付问题 **16 笔（32%）**、退款退货 **13 笔（26%）**，合计占 58%
- **退款退货是最大处理瓶颈**：平均处理时长高达 **45.2 小时**，远高于支付问题（5.2h）、商品咨询（0.9h）
- **处理时长与满意度显著负相关**：Pearson 相关系数 **-0.54**，处理越久满意度越低
- **渠道**：在线 34 笔、电话 16 笔，**邮件渠道为 0**

### 异常信号（需主管重点关注）

1. **重复扣款 / 扣款异常反复出现** —— T012、T022、T030、T032、T046、T050 等多笔均涉及"扣了两次钱""多扣了 100 块"，其中 **T046 明确提到"上个月也有过"**，说明支付系统存在长期未根治的 bug，建议最高优先级排查。

2. **退款退货处理超时且满意度极低** —— 超长处理（>48h）的 5 笔全部集中在退款退货（最长 120 小时），且未解决工单 8 笔中 **退款退货占 5 笔**，退款/退货流程存在明显积压与流程瓶颈。

3. **低满意度工单占比高** —— 满意度 ≤2 分的工单多达 **27 笔（54%）**，多与超长处理时长、客服/机器人体验相关。

4. **客服体验类投诉集中** —— 4 笔投诉全部指向客服态度（T010）、发货质检（T024）、等待时间长（T034）、机器人无效（T044）。

## 技术实现

| 项 | 选择 |
|----|------|
| 语言 | C++17（MSVC 2022 工具集 14.34） |
| JSON 解析 | [nlohmann/json](https://github.com/nlohmann/json) 单头文件（`third_party/json.hpp`） |
| 构建 | CMake + Visual Studio 2022 生成器 |
| 可视化 | ECharts 5（CDN 引入），中文交互式 Dashboard |

### 项目结构

```
TicketAnalysisProject/
├── task5_tickets.json         # 工单数据
├── task5_ticket_fields.md     # 字段说明
├── third_party/json.hpp       # nlohmann/json 单头文件
├── src/
│   ├── ticket.h/.cpp          # 工单结构体 + JSON 解析
│   ├── analyzer.h/.cpp        # 8 维度统计 + 6 类异常检测规则
│   ├── report.h/.cpp          # HTML Dashboard 生成
│   └── main.cpp               # 串联：读 JSON → 分析 → 写 dashboard.html
├── CMakeLists.txt
├── build.bat / run.bat        # 编译 / 编译+运行脚本
└── output/dashboard.html      # 生成的交互式 Dashboard(交付物)
```

### 如何构建与运行

Windows 环境（需安装 Visual Studio 2022 + CMake）：

```bat
run.bat
```

或手动：

```bat
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release
build\Release\ticket_analysis.exe
```

运行后生成 `output/dashboard.html`，用浏览器打开即可查看交互式分析结果。

> 说明：Dashboard 通过 CDN 引入 ECharts，需联网查看。如需离线，可下载 `echarts.min.js` 到本地并在 HTML 中替换 CDN 地址。

## AI 工具使用情况

本项目使用 **Claude Code（AI 编程助手）** 辅助完成，人工负责需求确认与结果审查：

- **需求分析**：解读任务要求，梳理字段含义与数据特征
- **方案设计**：设计 8 个分析维度与 6 类异常检测规则（含阈值与判断依据）
- **代码生成**：生成 C++ 源码（ticket / analyzer / report / main 四个模块）、CMake 构建脚本
- **调试**：定位并修复编译错误（JSON 类型声明错误、raw string 被 `)"` 提前截断等）
- **文档**：生成 README 与图表配置

人工（用户）完成：确认技术选型（C++ / HTML Dashboard / 中文）、审查分析结论的合理性。
